# Controlled platform integration

The candidate is integrated on a local branch only. Existing sessions retain their adapter; new sessions default to the legacy runtime. Both `SCRY_BROWSER_ADAPTER=playwright_mcp` and `SCRY_BROWSER_PLAYWRIGHT_MCP_ENABLED=true` are required to select the candidate. This is not customer activation.

The API remains authoritative for authentication, workspace scope, immutable Run origins, ordered encrypted commands, ownership and finalization. Praxis uses the pinned official browser adapter in a private child, with an independent browser/recorder custodian. Chronicle admits exact native screenshot and video receipts. The dashboard reads only authorized admitted bytes. No production package imports this experiment directory.

Interrupted interactions are never automatically replayed. A durable dispatch marker and action result distinguish uncertain execution from unavailable subsequent observation. Recovery closes only the admitted evidence prefix and does not restore a browser to repeat an action.

Capture is a native real-time MP4, with best-effort targeted black overlays; no DOM reconstruction. Private capture directories are authorized in Chronicle before recording starts. Recovery can admit a finalized recording from that reservation only. Partial coverage remains explicitly partial. Historical evidence remains unchanged.

## Operating bounds and residual limits

- Chromium only; pinned official adapter and paired alpha browser driver. No
  claim of Safari, mobile, desktop, every website, or unbounded concurrency support.
- Fixed 1280 × 720 capture at 20 fps. Recorder bounds are 120 MiB/15 minutes;
  reaching a bound yields partial footage. Integration worker memory limit: 3 GiB,
  with heavy targets exercised in bounded batches. This is not a memory-leak proof.
- Masking remains optional best effort, never a browser-command approval service.
  The existing text heuristic falsely classified `API-worker-Chronicle` as a key
  during the GitLab comment. That false positive is recorded, not hidden or
  described as an application defect. Recognition misses/false positives remain
  possible; review evidence before sharing.
- A timeout or loss after dispatch can yield UNKNOWN. Recovery does not promise
  exactly-once external effects; it prevents automatic replay and preserves facts.
- File upload, arbitrary code/evaluation, raw network dumps and browser installation
  are intentionally absent from the exposed tool profile. No OCR/quarantine
  service or DOM reconstruction was introduced.
- Native screenshots are available after admission; video is available after
  finalization. This is not live video streaming.

## Reproduction and activation boundary

Build `Dockerfile.integration` from the repository root and run
`docker compose -f experiments/browser-foundation/compose.integration.yml up -d`.
The Dockerfile intentionally starts from the earlier locally qualified image;
this lab recipe is not a production image distribution/deployment plan.
Run `platform-integration.mjs` in the API container for complete-path proof.
`platform-console.mjs` uses public tools with a read-only fictional-input mount;
`platform-ten-app-report.mjs` verifies downloaded videos against actual Run state.
`platform-recovery.mjs prepare`, then `dispatch`, creates the owned fault fixture;
pause/kill only the observed worker controller, restart that worker, and `verify`.
Do not replace natural claims with manual database grants or repeat the save.

The artifact receipt bundle is in the main workspace under
`artifacts/assurance/browser-foundation-integration-20261031/`: complete-path
receipt/video, recovery receipt/video, verified ten-app report, and dashboard,
Penpot and GitLab screenshots. Private fixture passwords are not copied there.

The candidate remains default-off behind both selection flags. Existing sessions
retain immutable adapter identity; there is no silent fallback between engines.
Before any later activation, choose the supported deployment resource bounds and
review the evidence/UX. Drain candidate Runs before disabling its worker support
or rolling back binaries. Main merge and remote deployment remain separate decisions.
